# 为方法词典添加一个方法

这是「社会科学量化方法自学手册」的维护入口。应用内从「方法词典 → 添加方法」进入。先写一份 JSON 草稿，在副本里检查效果，最后入库；无需直接改写两份大型数据文件。

## 最短操作流程

需要 Python 3.10 或更高版本，仅使用标准库，不需要 pip，不联网，不调用 AI，不运行草稿中的代码。在终端进入本目录（app/contribute）：

```text
python method_tool.py catalog
python method_tool.py template --family D --sub "匹配与响应面" --out new-method.json
python method_tool.py check new-method.json
python method_tool.py preview new-method.json --out ../../../方法预览
python method_tool.py add new-method.json
python method_tool.py check-app
```

`template` 根据当前数据分配该方法族的下一个编号，生成空模板。示例中的 D 和子类只是操作示范，不代表任何新方法都该放在这里。`catalog` 列出可用分类、历史节点、问题群和已有资源编号。选择不存在的子类时，入库会在该方法族下建立该子类；同名子类有多个时追加到第一个，保留原结构。

`check` 只检查，不写入。它同时指出尚缺的教学内容、无效编号、资源缺口和链接格式。填写 `待填写`、TODO 或 example.com 等占位内容不能入库。

`preview` 必须指向一个尚不存在、且不在当前 app 内的新目录。工具会完整复制 app 并在副本中新增方法，正式包和读者记录不变。在预览目录运行 `python -m http.server 8772 --bind 127.0.0.1`，浏览器打开 `http://127.0.0.1:8772/#method/新编号`。请使用不同于正式应用的端口，预览笔记不作为正式记录。

`add` 会重新校验后写入当前 app；写前自动备份需要修改的文件到 `backups/日期-编号/`。入库时发生异常会恢复这些原文件。不要同时运行两个维护命令，不要在写入期间关闭进程。备份用于本地恢复，不随软件发布。

`--app 路径` 可在命令前指定另一份 app，例如 `python method_tool.py --app "D:/副本/app" check new-method.json`。不要对旧版副本误操作。编号限「大写方法族字母 + 两位数字」，每族最多 99 个；超过前需同时升级学习记录中的编号规则。

## 六个关键问题怎样写

| 字段 | 读者真正需要知道的事 |
| --- | --- |
| q1 | 能解决什么问题？用具体的社会科学问题说明适用情境，与容易混淆的方法有什么区别。 |
| q2 | 原理是什么？先交代变量和单位，再用小数字走一遍。出现符号就当场解释；不能只写“核对上下限、检查模型”。 |
| q3 | 开始前准备什么？一行代表谁、每列是什么、需要什么研究设计、量尺、样本结构和假设；没有通用样本量阈值时不要硬给一个数。 |
| q4 | 怎样看结果？给明确的阅读顺序。readout 表逐项解释重要输出，不能只写“看显著性”“解释系数”。 |
| workflow | 怎样用？按顺序写出至少四个可执行步骤：准备数据、拟合／计算、诊断、读结果与报告。工具将它同时生成 q5。 |
| q6 | 结论能说到哪里？结合本例说明不能推出什么、哪些条件会使结论失效、怎样报告不确定性。 |

`plain` 是列表里的一段白话概述，不是口号。`example` 要有完整数字和计算或输出解读，所有虚构数据明确作为教学示例。`self_check` 给一道能自己回答的练习，并解释答案。

每行 `readout` 按下面顺序填写：

1. 指标的规范中文名称、英文名或软件输出标签，让读者找得到它。
2. 指标回答什么问题；正负、大小或增加减少分别意味着什么，并说明条件和量尺。
3. 一个有单位的数字例子，算出或解释这个数。不能把 p 值解释为假设为真的概率，不能把不显著写成“没有效应”。
4. 判断边界：区间、模型假设、方向约定、实际意义、误读风险。阈值必须有适用条件和来源。

数学地基 M 族沿用现有三列表头：符号或结果／怎样计算、怎样理解／容易弄错的地方。其余方法使用四列。至少三行只是结构检查下限，不是讲解完整性的标准：例如 RSA 仍需分别解释 a1、a2、a3、a4，且不能仅凭 a4<0 就断言一致性最好。

## 模板中的字段

- `schema_version`：固定为 1。
- `method`：名称、别名、分类、层级 L0–L4、六个问题、指标表、计算例子、步骤、代码、相关方法。`rp/pp/sp` 分别为 R 包、Python 包、Stata 命令；没有则为空数组。`code` 用语言名作键、代码字符串作值，R 使用小写 `r`。没有可执行实现时写 `复现路线` 并明确限制，不能把文字冒充已运行代码。
- `learning`：四个学习阶段。每阶段的 `outcome` 是读者具体能做的事，`targets` 是该方法的练习，`resource_urls` 必须来自本条目关联的课程资源。`term_note` 说明译名或易混概念，`term_source` 是实际核对过的中文来源 URL（没有则留空并在质量说明中解释）。
- `references`：新增来源。每个对象含唯一 `id`、`role`（origin/tutorial/application）、题名、作者、年份、出版物、DOI（无则空）、URL、语言、支持内容 `use`、精确定位 `locator`、核对日期 `checked_at`、访问方式 `access` 与实际可达状态 `availability`。至少两条真实来源；`origin` 来源应支持来历，`tutorial` 来源应支持操作／解释，不能靠一篇最新应用论文推定起源。查不到首次提出时在 `origin` 明说历史范围。
- `existing_reference_ids`：复用 context.sources 中的现有来源编号。新增来源不能覆盖已有编号。仍须实际复读、在 `quality.evidence_check` 写清定位。
- `resources`：新课程／教材／视频，字段与模板一致；`coverage` 只取 direct（专门讲解）、related（配套资料）、foundation（基础内容）。用具体课节和视频页，不用搜索结果页；`locator` 记录章节或时间段。
- `existing_resources`：复用现有资源时填写 `{ "id": "资源编号", "coverage": "direct" }`。工具只添加新方法的关联，不改变原有关联。
- `placement.cluster_ids`：所属问题群编号，至少一个。`history_node_ids` 可选，必须填真实匹配的已有历史节点；`history_note` 必填，解释选择或暂不挂入的原因。分类树会自动收录新条目。新增历史节点涉及时间线布局，需另行审查，不能把最新应用年份当方法诞生年份。
- `cases`：有真实应用案例时，按模板说明研究问题、设计、主要结果、边界和阅读任务；`refs` 只能引用上述新／旧来源。没有可靠案例时留空，填写 `quality.case_gap`，不能把教学数据包装成真实研究。
- `quality`：保留在维护稿中，记录术语、计算、代码与文献怎么核对。`resource_gaps` 含 zh_text/en_text/zh_video/en_video 四项；空白表示已有资源，否则如实说明缺口。校验器要求缺失类别有说明，不要求为凑数量加入低质量链接。

所有正文使用纯文本；段落用 `\n\n` 分开，可用 `**重点**`。不要写 HTML、脚本或内联事件。需要相互链接时，在相关方法列表填编号；不要自行拼不存在的方法链接。

## 自动接入哪些位置

入库自动更新 `atlas-data.js`、`learning-data.js`、`downloads-data.js`，以及有相关既存读物时的 `books-data.js`，并刷新 `index.html` 的资源指纹。新方法出现在搜索、中文／英文／别名检索、层级与软件标签、分类树、问题群、所选历史节点、分步学习和文献下载清单中。条目标题与简介只填写一次，工具同步两处数据，避免被旧学习资料覆盖。

参考文献自动进入下载清单；只凭链接不能标作“已内置”。已有下载清单或本地书籍通过相同 URL／DOI 关联时沿用原状态，不复制文件；新增文献默认为待下载。本工具不下载 PDF，不修改读者本机的 PDF、笔记、翻译缓存或学习状态。

## 检查到什么程度才算完成

机器可检查：必填字段和数据类型、占位文字、重复编号与名称、引用和关联是否存在、指标表列数、四阶段结构、课程语言与形式覆盖、URL 格式、引用对应关系和资源指纹。`check-app` 检查整库的编号、关联与文件指纹。

维护者／AI 仍需实际完成：逐条打开来源核实引用，运行或核算例子与代码，审查专业解释，检查下载权限，桌面与手机浏览器查看排版。只有链接格式正确，不代表链接可达；只有机器检查通过，不代表公式、译名或学术判断正确。引用来源与代码未核实时要明确说尚未完成。

预览时依次检查：能搜到新方法 → 标签筛选正确 → 六个问题完整 → 指标表不挤压 → 四个学习步骤能展开 → 相关方法和图谱能点开 → 课程指向对应内容 → 新文献出现在下载清单。既有方法仍应可用。

## 后续 GitHub 发布

当前仅保留本地维护入口，没有上传。后续按用户明确安排发布时，先确认公开范围、仓库和发布版本。完整项目根目录包含历史稿和维护文件，不能直接整目录上传。

发行包应排除 `contribute/backups/`、草稿、测试目录、`__pycache__`、本机学习导出、私人 PDF、缓存、密钥和凭据。已接受的 `contribute/entries/` 仅保存公开来源和教学内容，可作为维护依据。原文 PDF、字体、词典及其他第三方材料须逐项确认再分发许可；不能确认许可的文件改为来源链接。代码许可证由用户决定，不擅自为其指定。

本入口不包含安卓原工程和原签名；不可声称已具备安卓覆盖更新能力。Windows 原生外壳也应保留现有可执行文件及其来源信息，后续发布说明如实交代构建材料是否齐全。
## 历史年表的关联

`catalog` 的 `history_nodes` 会先列出当前历史年表的事件（`view` 为“历史年表”），再列出保留兼容的旧主线节点。给新方法填写 `placement.history_node_ids` 时，应优先选择有明确历史依据的年表事件 ID；工具会同步更新 `history-data.js` 的方法链接。不要因为方法使用同一计算工具，就把它挂到一个不相干的早期年份。没有合适事件时留空，并在 `history_note` 中说明。

新增历史事件需单独编辑 `app/history-data.js` 的纯 JSON 数据：沿用稳定事件 ID，给出确切年份、主题 `lane`、标题、发生了什么 `summary`、今天的用途 `change`、解释边界 `caution`、相关方法 `methods` 与文献 `refs`。在 `sources` 中填写真实作者、题名、年份、原始来源 URL，区分事件日期、出版日期和网页上线日期。按年份排序，补齐相应年代分组；更新页面资源指纹后运行 `check-app`。已有方法的六问正文和学习记录编号不应因年表维护被覆盖。
